# Отчет по лабораторной работе

## Тема

Настройка процесса непрерывной интеграции с использованием GitHub Actions.

## Цель работы

Цель лабораторной работы — настроить CI-процесс для проекта, чтобы автоматизировать проверку качества кода при каждом изменении в репозитории.

## Выбранный проект

Для выполнения работы был использован собственный учебный проект на языке Python. Проект содержит модуль `calculator.py` с несколькими функциями и набор автоматических тестов.

В проекте отсутствовали готовые CI-конфигурации, поэтому файл workflow был создан вручную.

## Структура проекта

```text
app/calculator.py              # основной код проекта
tests/test_calculator.py       # автоматические тесты
.github/workflows/ci.yml       # workflow GitHub Actions
Dockerfile                     # файл для сборки Docker-образа
requirements.txt               # зависимости проекта
pyproject.toml                 # настройки проекта, ruff и pytest
```

## Реализованные функции

В проекте реализованы функции:

1. `add()` — сложение двух чисел.
2. `divide()` — деление чисел с проверкой деления на ноль.
3. `factorial()` — вычисление факториала числа.
4. `is_even()` — проверка числа на четность.

По условию лабораторной работы необходимо было покрыть тестами минимум 3 функции или метода. В данной работе тестами покрыты все 4 функции.

## Тестирование

Для тестирования используется библиотека `pytest`. Также подключен `pytest-cov`, который формирует отчет о покрытии кода.

Команда запуска тестов:

```bash
pytest
```

В workflow GitHub Actions эта команда выполняется автоматически на этапе `Test`.

## Lint

Для статического анализа кода используется `Ruff`. Он проверяет стиль кода, потенциальные ошибки и несоответствия стандартам.

Команда запуска линтера:

```bash
ruff check app tests
```

В workflow GitHub Actions эта команда выполняется автоматически на этапе `Lint`.

## Build

На этапе сборки выполняются два действия:

1. Сборка Python-пакета командой:

```bash
python -m build
```

2. Сборка Docker-образа командой:

```bash
docker build -t ci-github-actions-lab:latest .
```

Таким образом, этап `Build` создает итоговый артефакт проекта.

## GitHub Actions workflow

Workflow находится в файле:

```text
.github/workflows/ci.yml
```

Он запускается автоматически при:

- `push` в ветку `main`;
- `pull_request` в ветку `main`.

Pipeline состоит из трех jobs:

1. `lint` — проверка кода линтером.
2. `test` — запуск тестов и формирование coverage-отчета.
3. `build` — сборка Python-пакета и Docker-образа.

Этапы связаны зависимостями: сначала выполняется `lint`, затем `test`, затем `build`.

## Фрагмент workflow

```yaml
on:
  push:
    branches: ["main"]
  pull_request:
    branches: ["main"]
```

Этот фрагмент означает, что pipeline автоматически запускается при отправке изменений в ветку `main`.

## Результат

В результате выполнения лабораторной работы был создан проект с настроенным CI-процессом. При каждом push в ветку `main` GitHub Actions автоматически запускает pipeline, который выполняет статический анализ кода, запускает тесты с coverage и собирает проект.

Если все этапы проходят успешно, workflow отображается зеленым статусом во вкладке **Actions**.

## Вывод

В ходе лабораторной работы был изучен и реализован процесс непрерывной интеграции. GitHub Actions позволяет автоматически проверять качество кода, запускать тесты и выполнять сборку проекта при каждом изменении в репозитории. Это снижает вероятность ошибок и ускоряет процесс разработки.
